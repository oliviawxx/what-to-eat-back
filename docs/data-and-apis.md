# 前端数据与接口说明

本文档说明：**哪些地方需要后端数据**、**哪些数据存本地**、**预留接口与可做程度**。

---

## 一、需要后端数据的模块

| 模块 | 页面/功能 | 需要的数据 | 当前状态 |
|------|------------|------------|----------|
| **登录/注册** | 个人页-登录模态框 | 邮箱+验证码校验、登录态 token、用户信息回填 | 仅前端调试（点击登录即视为已登录），需接登录/注册接口 |
| **个人资料** | 个人页-头像/昵称/签名/邮箱/简介 | 拉取当前用户资料、上传头像到 CDN 返回 URL | 昵称/签名等已可编辑并**存本地**；头像为本地临时路径，后端需提供「上传头像」接口并返回 URL |
| **好友/聊天** | 好友聊天页、聊天详情页 | 好友列表、会话列表、消息记录、未读数 | 目前为假数据（首字母头像），需会话列表与消息接口 |
| **随机选餐** | 首页-今天吃什么 | 推荐结果（商家、菜品）、黑名单、筛选条件 | 目前为假数据，需推荐接口与筛选参数 |
| **约饭/榜单** | 约饭列表、榜单位置、商家详情 | 约饭列表、地图点位、商家详情、评价列表 | 目前为假数据，需列表与详情接口 |
| **约饭发布** | 发布页-约饭编辑 | 提交约饭（日期/时间/地点/标签等）、商家信息 | 目前仅前端表单，需「发布约饭」提交接口 |
| **评价发布** | 发布页-评价 | 提交评价（评分、内容、图片/视频） | 目前仅前端表单，需「发布评价」接口 |
| **个人标签/模板** | 个人页-标签选择、约饭模板 | 用户标签列表、约饭模板列表的增删改查 | 标签已可添加并仅存前端；模板为假数据，需接口 |
| **待办消息** | 个人页-待办入口、待办列表页 | 待办列表、已读状态 | 目前为静态页，需待办接口 |

## 二、本地存储（已做 / 建议）

| 存储键 | 含义 | 写入时机 | 读取时机 |
|--------|------|----------|----------|
| **`localUserInfo`** | 当前用户资料（头像、昵称、签名、邮箱、简介） | 个人页编辑任意项或上传头像后 | `app.onLaunch` 读入 `globalData.localUserInfo`；个人页 `onShow` 合并到页面 `userInfo`；AI 聊天等用 `globalData.localUserInfo.avatarUrl` 展示当前用户头像 |
| `logs` | 调试日志（可选） | 启动时 | 日志页 |
| （后续可加）`token` | 登录态 | 登录接口返回后 | 请求头或全局请求封装 |
| （后续可加）`addressFilter` / `peopleFilter` | 首页筛选条件 | 用户切换筛选时 | 首页 onLoad |

**头像说明：**

- 当前：上传头像后保存的是**本地临时路径**到 `localUserInfo.avatarUrl` 并同步到 `globalData`，个人页与 **AI 聊天用户气泡**会使用该头像；重启后若临时文件被清理则头像会丢失。
- 建议：后端提供「上传头像」接口，返回**永久 URL**；前端将 URL 写入 `localUserInfo.avatarUrl` 并存本地，这样所有端（含真机）和多端同步一致。当前实现已为「先写本地 + globalData」留好扩展，只需在上传成功后把返回的 URL 写入即可。

## 三、预留接口（按模块）

以下为后续对接后端时建议的接口形态（仅作占位与约定，具体 path/方法以实际后端为准）。

- **登录/注册**
  - 发送验证码：`POST /auth/send-code`（邮箱）
  - 登录/注册：`POST /auth/login`（邮箱 + 验证码）→ 返回 token、用户基本信息（含头像 URL、昵称等）
- **用户信息**
  - 获取当前用户资料：`GET /user/me`（需 token）
  - 上传头像：`POST /user/avatar`（file）→ 返回头像 URL
  - 更新资料：`PATCH /user/me`（昵称、签名、邮箱、简介等）
- **聊天/好友**
  - 会话列表：`GET /chat/sessions`
  - 某会话消息：`GET /chat/messages?sessionId=xx`
  - 发送消息：`POST /chat/messages`
- **随机选餐**
  - 推荐：`POST /recommend` 或 `GET /recommend`（传入筛选条件）→ 返回商家/菜品
- **约饭/榜单**
  - 约饭列表/地图点位：`GET /yuefan/list`（或带地图范围）
  - 商家/约饭详情：`GET /yuefan/:id` 或 `GET /merchant/:id`
- **发布**
  - 发布约饭：`POST /yuefan`
  - 发布评价：`POST /review`
- **个人**
  - 标签/约饭模板：`GET/POST/PATCH/DELETE /user/tags`、`/user/templates`
- **待办**
  - 待办列表：`GET /todo`；已读：`PATCH /todo/:id/read`

## 四、当前能做到的程度（小结）

- **已做**
  - 个人资料（昵称、签名、邮箱、简介）编辑后**存本地**并同步到 `globalData`，个人页与 AI 聊天（当前用户头像）展示一致。
  - 头像：选图后**存本地路径 + globalData**，个人页与 **AI 聊天用户气泡**使用当前用户头像；重启后依赖临时文件是否仍在，长期需改为后端 URL。
- **不行 / 需后端**
  - 登录态、跨设备同步、永久头像 URL、好友/会话/消息、推荐与约饭真实数据、发布提交、待办等，均需后端接口支持。
- **已留好扩展**
  - `app.globalData.localUserInfo` + `wx.setStorageSync('localUserInfo')` 统一读写；上传头像处只需在拿到后端返回 URL 后写入 `localUserInfo.avatarUrl` 并同步 storage/globalData，即可在所有已使用「当前用户头像」的界面生效。
